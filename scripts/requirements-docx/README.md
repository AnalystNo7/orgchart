# Сборка DOCX реестра требований

Собирает `harness/REQUIREMENTS.md` в Word-документ в оформлении
корпоративного образца заказчика.

```bash
node scripts/requirements-docx/build.mjs ["путь/к/файлу.docx"]
```

По умолчанию пишет `Требования OrgChart Modeler.docx` в корень репозитория.
**Готовый .docx в git не коммитится** — источник истины остаётся `.md`,
документ пересобирается скриптом.

## Как устроено

`template/` — шаблон-донор оформления, извлечённый из образца заказчика
(HR-портал, редакция 30.07.2026). Содержит только оформление, без содержания:
стили (`styles.xml`), нумерацию списков (`numbering.xml`), три колонтитула
с номером страницы, тему, таблицу шрифтов, настройки и rels.
`document.xml`, `docProps/core.xml` и `docProps/app.xml` в шаблоне намеренно
отсутствуют — их генерирует скрипт.

Скрипт разбирает markdown реестра и раскладывает его по четырём секциям
документа:

| Секция | Ориентация | Содержание |
|---|---|---|
| 1 | портрет, без колонтитула | титульный лист |
| 2 | портрет | оглавление (поле TOC), сводка, классификация, реестр, служебные разделы |
| 3 | **альбом** | матрица связности (таблица на 8 колонок) |
| 4 | портрет | журнал изменений документа |

Соответствие разметки:

- `BR-001 — Название` → заголовок 3 уровня (карточка требования);
- группы требований и подразделы служебной части → заголовок 2 уровня;
- остальные заголовки → 1 уровень, с закладкой `_Toc…` для оглавления;
- `- **Метка:** значение` → абзац с отступом 567 и полужирной меткой;
- прочие пункты списков → маркированный список (стиль `a4`, маркер «–»);
- таблицы → границы 0,5 пт, шапка с заливкой `E7E6E6` и повтором на страницах.

Титульный лист (название проекта, редакция, источник требований) задан
константой `TITLE` в начале скрипта.

## Проверка результата

LibreOffice в среде разработки может быть недоступен, поэтому основная
проверка — структурная: `unzip -t` и подсчёт секций, таблиц, карточек и
закладок в `word/document.xml`. При открытии в Word оглавление нужно
обновить: правый клик по нему → «Обновить поле» (или F9).
