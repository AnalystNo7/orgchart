## 2026-08-22 — Величины на интервалах нельзя складывать без нормировки на длительность
- Что случилось: доли выручки P&L искажались до ×12, трансфертные продажи
  завышались в число месяцев; периоды обеспечения хранились, но не читались
- Причина: в одной базе живут два стиля привязок — импорт из Excel создаёт
  12 строк-месяцев на годовую работу, ручной ввод в справочнике (и AI/undo) —
  одну строку на весь период; расчёт складывал сырой fte по строкам и умножал
  часы всего периода на каждую строку — ответ зависел от способа ввода данных
- Урок: мера вклада интервальной записи — величина × длительность (FTE-часы);
  расчёт обязан давать один ответ при любой нарезке записей — проверять
  эквивалентность «помесячно ≡ одним куском» отдельным смоук-случаем

## 2026-08-21 — Видимые «размышления вслух» — главный пожиратель бюджета времени
- Что случилось: ответ DeepSeek — сотни строк планирования с внутренними
  именами инструментов; таймауты частично от самой этой генерации
- Причина: промпт не задавал стиль ответа — модель честно думала вслух
  терминами своего API прямо в видимый текст
- Урок: стиль ответа (статус → результат, без внутренних имён) — часть
  технического промпта; утечку имён страховать фильтром кодом, а не только
  инструкцией

## 2026-08-21 — Таймаут стрима — не исключение, а тихий finish: other
- Что случилось: обрыв по таймауту выглядел законченным ответом; [AI_DONE]
  вместо ошибки, пометки обрыва нет — пользователь принял это за зависание
- Причина: у streamText таймаут завершает поток без исключения; catch не
  срабатывает, успех можно определить только по finishReason === "stop"
- Урок: при потоковой генерации проверять finishReason всегда; «done» от
  SDK ещё не значит «ответ доведён до конца»

## 2026-08-21 — Узким местом оказался свой потолок, скопированный с чужой платформы
- Что случилось: длинные reasoning-прогоны обрывались на 280 с; лимит шагов
  ни разу не достигался
- Причина: таймаут цикла был привязан к maxDuration Vercel, хотя приложение
  работает на локальном dev-сервере без платформенных лимитов
- Урок: лимиты привязывать к реальной среде исполнения (process.env.VERCEL),
  а не к худшему случаю; непотоковая генерация прятала прогресс — streamText
  показывает, жив ли шаг

## 2026-08-20 — 99% времени AI-ответа — латентность модели, а не наш код
- Что случилось: чат падал по таймауту 300 с; инструментирование показало
  инструменты 0.5 с, модель 299.6 с
- Причина: время модели растёт с объёмом входа. Результаты инструментов
  остаются в истории и переотправляются на каждом шаге, поэтому опасна сумма
  за прогон (180 КБ), а не размер отдельного вызова. Плюс: модель не знает
  nextOffset заранее, поэтому параллельные вызовы пагинированного инструмента
  в одном шаге дают дубликаты
- Урок: оптимизировать не код, а объём входа; мерить сумму байтов за прогон;
  пагинированный инструмент явно помечать «не вызывать параллельно»

## 2026-08-20 — Лимит провайдера бывает на ОДИН блок входа, а не на вывод
- Что случилось: чат падал «text size 90131 exceeds limit 65536» после вызова
  инструмента, хотя ответ модели был короткий
- Причина: результат инструмента возвращается в модель одним текстовым блоком;
  провайдер режет по размеру блока, а pretty-print JSON раздувал его на треть
- Урок: различать лимит входа и потолок вывода — лечится пагинацией результата,
  не разбиением генерации; считать байты (кириллица 2 б/симв), JSON не рвать

## 2026-08-19 — Merge переписанной ветки воскрешает старые папки миграций
- Что случилось: migrate dev падал P3006 в shadow-БД («тип уже существует»);
  до этого новые роуты падали на undefined-модели Prisma-клиента
- Причина: pull с merge разошедшихся историй вернул до-переписную папку
  20260226_orgchartv1 рядом с новым init; shadow-БД прогоняет ВСЕ папки подряд.
  А migrate/generate после pull не запускались вовсе (package.json не менялся)
- Урок: после pull с миграциями — migrate dev/deploy + generate + рестарт;
  при P3006 сверить dir prisma\migrations с git ls-tree origin/<ветка>;
  для применения без shadow-БД есть migrate deploy; reset — никогда на живых данных

## 2026-08-19 — Нативная HTML-валидация молча глотает submit
- Что случилось: «Сохранить» не давал ни запроса, ни ошибки; тест-кнопка работала
- Причина: type="submit" запускает браузерную проверку required/min/max/step —
  при нарушении submit-событие не срабатывает вовсе; type="button" её обходит
- Урок: в формах с JS-обработкой ставить noValidate и показывать ошибки полей
  явно; кнопка-«обходчик» рядом с submit маскирует проблему

## 2026-08-19 — openai(model) в @ai-sdk/openai v3 ≠ Chat Completions
- Что случилось: дефолтный вызов бьёт в Responses API — совместимые шлюзы его не имеют
- Причина: в v3 SDK Responses стал дефолтом; для шлюзов нужен явный .chat(model)
- Урок: при подключении OpenAI-совместимых прокси всегда проверять транспорт в d.ts

## 2026-08-19 — Git-прокси сессии не удаляет remote-ветки
- Что случилось: `git push origin --delete <ветка>` → HTTP 403
- Причина: прокси удалённой среды разрешает push, но запрещает удаление ссылок
- Урок: удаление веток на GitHub делать руками через UI или локальный git владельца
