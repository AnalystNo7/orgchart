# PLAN: бюджет контекста AI-чата

Дата: 2026-08-20

## Шаги

1. `src/lib/ai/limits.ts` — новый модуль с константами
   `AI_ROUTE_MAX_DURATION_SEC`, `AI_LOOP_SAFETY_MS`, `AI_RUN_CONTEXT_BUDGET_BYTES`.
2. `tool-executor.ts` / `getOrgStructure` — колоночный формат `columns`/`rows`
   вместо массива объектов; ФИО руководителя → флаг `hasHead`.
3. `tools.ts` — в описании `get_org_structure` расшифровать формат и увести
   общие вопросы на `get_org_metrics` / `run_health_check`.
4. `system-prompt.ts` — секция «Порядок работы с оргструктурой» (≤10 строк);
   в секцию про неполные результаты дописать `run_health_check` / `get_insights`.
5. `tools.ts` — `READ_ONLY_TOOLS`, кэш вызовов за прогон и предохранитель
   бюджета в `wrapExecute`; `ToolRunStats` расширить полями `cached`, `bytesOut`.
6. `orchestrator.ts` + `route.ts` — таймаут цикла с запасом 20 с до `maxDuration`.
7. `orchestrator.ts` — в `[AI_DONE]` и `[AI_CHAT_ERROR]` добавить объём
   результатов и число попаданий в кэш.
8. `npx tsc --noEmit`; прогнать запросы из чек-листа BRIEF.

## Альтернативы

- **Новый инструмент `get_org_tree`** (компактное текстовое дерево, ~25 КБ на всю
  структуру): отвергнута, потому что 34-я схема утяжеляет служебный контекст на
  каждом шаге, а колоночный формат даёт сопоставимую экономию и сохраняет `id`,
  без которых не вызвать `get_department_details` / `move_department`.
- **Разделить инструменты на read/write и подключать write по намерению**
  (−7 КБ на шаге): отвергнута, потому что экономия вдвое меньше, чем от шагов 2–5,
  а цена — модель не находит нужный инструмент и отвечает отказом вместо действия.
- **Поднять `timeoutSec`/`maxDuration` до 600**: отвергнута, потому что не
  устраняет причину, а удваивает ожидание пользователя; на тарифе Vercel Hobby
  лимит функции всё равно 300 с.

## Риски

- 🟡 Модель не поймёт колоночный формат `columns`/`rows` → следим: расшифровка
  в описании инструмента; при сбое в ответе будут перепутаны поля — проверяем на
  первом же прогоне «покажи 5 подразделений с наибольшим FTE».
- 🟡 Кэш вернёт устаревшие данные после мутации внутри того же прогона →
  следим: кэшируем только read-only инструменты, кэш живёт один прогон.
  Остаточный случай — `run_whatif_scenario` меняет клон, а не текущий сценарий.
- 🟡 Предохранитель сработает на легитимном сложном запросе → следим: отказ
  текстовый и подсказывает агрегаты, модель может ответить по частичным данным.
- 🟢 `hasHead` вместо ФИО: анализ структуры не теряет сигнал (важен факт
  наличия руководителя), ФИО берётся через `get_department_details`.
- 🟢 `maxDuration` в `route.ts` остаётся литералом (Next читает статически) —
  расхождение с `limits.ts` ловится только глазами; помечено комментарием с обеих сторон.
