# BRIEF: Пагинация результатов инструментов AI
Дата: 2026-08-20

## Формулировка своими словами
Чат-ассистент падает, когда инструмент возвращает слишком большой результат:
провайдер отвергает входящее сообщение, если один текстовый блок превышает его
лимит (у Gonka/MiniMax — 65536). Нужно, чтобы результаты инструментов
автоматически укладывались в лимит: отдавать страницу данных + сводку +
подсказку модели, как дозапросить остальное. Лимит должен настраиваться
в пресете LLM, потому что у разных провайдеров он разный.

## Контекст
- Ошибка: `messages[7].content entry: invalid shape: [0].text size 90131
  exceeds limit 65536` при `!ai что можно сделать?`
- Виновник — `getOrgStructure` (`tool-executor.ts:158-204`): отдаёт все
  подразделения без лимита + pretty-print `JSON.stringify(x, null, 2)`
- Все 33 инструмента проходят через `wrapExecute` (`tools.ts:7-18`) —
  единая точка врезки; `executeTool` всегда возвращает строку
- Ограничений размера нет (кроме `.slice(0,10/30)` в analyze_skill_gaps)
- Это лимит на ВХОД, поэтому механика «генерация в 1–8 запросов» из другого
  проекта пользователя тут не применима (она про потолок ВЫВОДА)

## Критерии успеха
- [ ] `!ai` на большом сценарии не даёт `exceeds limit`, ответ приходит
- [ ] Усечённый результат содержит `_truncated`, `shown`, `total`, `nextOffset`,
      подсказку; JSON всегда валиден (не рвётся посреди структуры)
- [ ] Модель может дозапросить следующую страницу через `offset`
- [ ] Лимит настраивается в /admin/llm, дефолт 60000 байт при env-fallback
- [ ] Малый сценарий (21 подразделение) работает как раньше, без `_truncated`
- [ ] tsc --noEmit без новых ошибок
