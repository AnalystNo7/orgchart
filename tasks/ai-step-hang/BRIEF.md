# BRIEF: зависание шага AI без вызовов инструментов
Дата: 2026-08-20

## Формулировка своими словами
После сжатия контекста (`9a36b8c`) таймаут остался, но логи показали другую
картину: шаги с вызовами инструментов отрабатывают за 3.5 с, а шаг финального
ответа висит 273 с и не выдаёт ничего. Причину зависания из данных приложения
сейчас отличить нельзя — `generateText` непотоковый и молчит до конца ответа.
Нужно сначала собрать данные, которые однозначно укажут на причину, и заодно
перестать терять всё собранное при обрыве.

## Контекст
- Модель MiniMax-M2.7 через шлюз Gonka, reasoning, `<think>` приходит в content.
- Прошлая гипотеза (объём входа) **опровергнута** — см. доказательства ниже.
- SDK `ai@6.0.116` поддерживает `experimental_onStepStart` с полем `messages`
  и `TimeoutConfiguration = { totalMs, stepMs, chunkMs }`.

### Доказательства
| Факт | Откуда |
|---|---|
| Шаги #1 и #2 — 3.5 с каждый, шаг #3 — 273 с и пусто | `[AI_STEP]` + `[AI_CHAT_ERROR]` прогона |
| Весь контекст прогона 33.2 КБ — мал | `[AI_CHAT_ERROR] … 33.2 КБ` |
| Фиксированные ~10.7k токенов промпта и схем стоят ~3 с | быстрые шаги #1/#2 при том же промпте |
| `calculate_pnl` вернул пустой массив, а не исключение | 207 Б = ровно envelope с `departments: []`; с одним подразделением 394 Б; `{"error": …}` ≈ 105 Б |
| Подразделения в сценарии есть | `get_unit_economics` отдал 32.5 КБ и читает `e.department.name` без падения |
| При обрыве диалог не сохраняется | `route.ts` `onError` шлёт `error` и закрывает поток |

## Критерии успеха
- [ ] В логе видно, какой пресет и модель отвечают и задан ли `maxOutputTokens`
- [ ] Перед каждым шагом в логе есть его номер и точный объём входа (`messages`)
- [ ] При обрыве видно, какой шаг висел, сколько и с каким входом
- [ ] В `[AI_TOOL]` видны аргументы — в частности `scenarioId` у `calculate_pnl`
- [ ] Ошибка внутри инструмента попадает в лог, а не только в ответ модели
- [ ] После обрыва диалог сохранён, в чате есть честная пометка о незавершённости
- [ ] `calculate_pnl` на пустом результате объясняет причину, а не молчит

## Открытые вопросы
- Зависание — это медленная генерация или мёртвое соединение? **Отложен**:
  непотоковый `generateText` их не различает. Ради ответа и собирается
  диагностика; следующий кандидат — `streamText` + `chunkMs`.
- Задан ли `maxOutputTokens` в активном пресете? **Отложен**: из сессии в БД
  не заглянуть, закрывается строкой `[AI_RUN]` на первом же прогоне.
- Верный ли `scenarioId` ушёл в `calculate_pnl`? **Отложен**: закрывается
  логом аргументов.
