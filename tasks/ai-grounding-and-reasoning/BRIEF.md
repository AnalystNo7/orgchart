# BRIEF: выдуманные сотрудники и суммы в ответах AI-чата, рассуждения на английском
Дата: 2026-09-10

## Формулировка своими словами
На вопрос «самые убыточные сотрудники» ассистент выдал таблицу с фамилиями («Анисимов А.С.»), стоимостью «10,6 млн ₽/год» и утилизацией по людям, хотя в справочнике сотрудники обезличены («сотрудник12»), а стоимости и загрузки по сотруднику нет ни в одном инструменте. Модель сгенерировала весь ответ. Нужно: (1) дать ассистенту реальные данные по сотрудникам, чтобы такой вопрос был ответим по фактам; (2) исправить единицы измерения в существующем инструменте, из которых родились «млн ₽/год»; (3) добавить в промпт правила, что делать при отсутствии разреза и как обращаться с именами; (4) скрыть рассуждения модели (идут по-английски) в UI, не теряя ответ.

## Контекст
- Ответ получен в AI-чате приложения (с `!ai`), пресет DeepSeek V4 Flash через Gonka.
- Похожих записей в `harness/LESSONS.md`/`DECISIONS.md` нет. Ближайшая история: `tasks/think-and-typography` — свёрнутый блок рассуждений уже делали и откатили (`084980d`), потому что Gonka/MiniMax присылал `<think>` без `</think>` и весь ответ уходил в скрытый блок. Урок оттуда: прятать можно только то, у чего известна граница.
- Промпт состоит из методической половины (редактируется в `/admin/settings/prompt`, строка в `AiPromptSetting` заменяет дефолт целиком) и технической (`buildTechnicalPrompt`, всегда добавляется из кода). Правила заземления должны жить в технической.
- Анонимизация из концепции в чат не реализована; имена не утекают только потому, что база уже обезличена.

## Критерии успеха
- [ ] Инструмент `get_employee_economics` возвращает по сотруднику: имя ровно как в БД, должность, категорию, подразделение, FTE, ставку ₽/час, стоимость ₽/год по производственному календарю, покрытие договорами в % и число договоров; сортировка по стоимости или покрытию; пагинация; поле `_units` с расшифровкой. Тест на фикстуре: 3 сотрудника с известными ставками/привязками дают ожидаемые числа с точностью до рубля.
- [ ] `get_unit_economics` отдаёт `annualCostPerFteRub`/`annualRevenuePerFteRub` с часами года и `contractCoveragePct` вместо «utilization», плюс `_units`; UI финансов (`/finance`) не затронут (свой расчёт).
- [ ] Техническая половина промпта содержит раздел «Данные и их отсутствие»: цифры только из инструментов; нет разреза → сказать и предложить доступный; имена ровно как в данных, ФИО не «восстанавливать»; агрегаты подразделения не переносить на людей; рассуждать кратко и по-русски. Стиль-правило 2 дополнено «отсутствие данных называть явно». Порядок работы: «стоимость/загрузка по сотрудникам — get_employee_economics, по подразделениям — get_unit_economics».
- [ ] `ChatMessage`: при наличии `<think>…</think>` рассуждение сворачивается в блок «Ход рассуждений» (закрыт по умолчанию), ответ показан целиком; при отсутствии закрывающего тега поведение прежнее (ничего не теряется). Юнит-проверка функции разбиения: закрытый тег, незакрытый, частичный хвост при стриме, два блока.
- [ ] На стенде заказчика: вопрос «!ai самые убыточные сотрудники» даёт таблицу с именами вида «сотрудник12» и числами, совпадающими с результатом инструмента (видно в чипах вызовов); рассуждения не отображаются в открытом виде (если DeepSeek присылает `</think>`).
- [ ] Регресс: `scripts/ai-retry-check` (45 + 14) проходит, `tsc` без новых ошибок, `next build` успешен.

## Открытые вопросы
- Присылает ли DeepSeek через Gonka закрывающий `</think>` — **отложен до живого прогона**; в песочнике провайдера нет. Если не присылает, сворачивание не сработает по построению, и останется только инструкция «рассуждай кратко и по-русски» плюс отдельное решение об эвристике границы.
- Что считать «утилизацией» по сотруднику — **решено в пользу покрытия договорами**: доля FTE сотрудника, обеспеченная привязками к договорам в отчётном году (`EmployeeContract.fte` с учётом периода). Фактической загрузки в данных нет, инструмент так и называет поле.
- Нужен ли маркер 【LLM】 бейджем и сторож на имена — **отложены по решению заказчика** («без дополнительных защит»).
