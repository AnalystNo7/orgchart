# Отчет (REPORT.md)

## 2026-09-09 — отмена прогона при обрыве клиента + повтор при раннем обрыве стрима

## Сделано
- `route.ts`: `AbortController` на запрос, `req.signal` + `cancel()` → прерывание прогона; `send` не пишет в закрытый поток, единственная точка закрытия `finish()`, heartbeat гасится при отмене; новый колбэк `onAbort` сохраняет частичный ответ с `context.cancelled` без единого `send`.
- `orchestrator.ts`: `signal` в очередь, паузы (`sleep` просыпается по abort) и `streamText`; слот освобождается слушателем abort сразу; повтор разрешён для «раннего» прогона (`isEarlyRun`: ≤1 шага, ≤`AI_RETRY_MAX_SHOWN_CHARS`, только read-only инструменты) и теперь срабатывает и на ошибку из стрима (`finish: other/error`), с пометкой в чате; при известной ошибке провайдера без повтора пользователь видит её текст, а не «таймаут»; `errorTextOf` читает `message` у «голых» объектов из SSE.
- `tools.ts`: `wrapExecute` не начинает работу после отмены; `READ_ONLY_TOOLS` экспортирован.
- Мок и тесты: режимы `fail_step2`, `drip`, `stream_error`, счётчик обрывов; кейсы 11–18. Итог: 45/45 интеграционных, 14/14 юнит.
- Документы: `LIMITATIONS.md` (строка 3), `PROJECT.md` (AI-ассистент, бюджеты, логи).

## Отклонения от плана
- Добавлен кейс 18 (ошибка внутри 200 SSE) и helper `errorTextOf`: план предполагал, что ошибка стрима всегда `Error`, а SDK отдаёт объект `{message, type}` — без helper повтор не срабатывал.
- Текст ошибки при обрыве без повтора заменён на текст провайдера с пояснением «автоповтор не выполнен, так как часть ответа уже показана» — план оставлял прежнюю формулировку про таймаут, она вводила в заблуждение.

## Сюрпризы
- Тест «отмена в очереди» при одновременном старте двух прогонов недетерминирован: слот первым брал отменяемый прогон. Исправлен порядок старта (300 мс), поведение кода было верным.
- Локальный PostgreSQL в песочнице останавливается между сессиями; перед прогоном тестов нужен `pg_ctlcluster 16 main start`.

## Записи в журналы (черновики, ждут подтверждения)
- DECISIONS: «2026-09-09. Отмена клиента прерывает прогон через один AbortSignal (req.signal + cancel()), отличаем отмену только по signal.aborted, не по имени ошибки. Причина: SDK сливает наш сигнал с тремя таймаутами в один, при abort не бросает из for await и не вызывает onError — по ошибке отмену от таймаута не отличить. Повтор после обрыва разрешён только для „раннего“ прогона (≤1 шага, ≤300 символов, read-only инструменты): выше — перерисовка ответа и повтор записи в БД дороже честной пометки об обрыве.»
- LESSONS: «2026-09-09. Отмена в UI не останавливала прогон на сервере: он держал слот очереди и слот Gonka и в конце писал в закрытый поток (Controller is already closed). Причина: ReadableStream без cancel(), req.signal не использовался, send без защиты. Урок: любой долгий серверный прогон получает AbortSignal запроса с первого дня, а запись в поток проверяет его состояние; ошибка стрима из тела 200 SSE приходит как объект {message,type}, не Error — текст ошибки извлекать helper-ом.»
