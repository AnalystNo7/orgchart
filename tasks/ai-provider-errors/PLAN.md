3. `orchestrator.ts` — lastActivityAt; в finish!=stop для "other" различать

4. `formatAIError` — ветки «too many concurrent requests» и «No output

5. `ai-store.ts` + `StreamingStatus.tsx` — фаза retry_wait.
6. `PROJECT.md`; tsc + build; сценарии из BRIEF.

## Альтернативы
- **maxRetries SDK вместо своего цикла**: отвергнута — SDK повторяет с
  короткими паузами (3 попытки за 7 с), слот шлюза живёт десятки секунд;
  нужны интервал 20 с и видимый статус.
- **Авто-повтор после chunk-обрыва**: отвергнута пользователем — стирает
  показанный текст, тратит минуты.
- **Детект 429 только по statusCode**: отвергнута — обёртки прячут статус;
  матчим и текст, и код.

## Риски
- 🟡 Повторы могут продлить ощущение «висит» до +60 с → следим: статус
  явно показывает «попытка N из 3», heartbeat живёт.
- 🟡 429 может прийти и от честного rate limit по токенам → следим:
  матчим именно «too many concurrent requests»; прочие 429 идут по
  прежней ветке без повторов.
- 🟢 Повторный прогон шага после паузы переиспользует кэш read-only
  инструментов.
