# BRIEF: реестр требований по Вигерсу
Дата: 2026-08-22

## Формулировка своими словами
Перенести шаблон реестра требований (методология Вигерса) из другого проекта
пользователя в harness/templates/ и создать рабочий экземпляр для OrgChart
Modeler, заполнив его ретроспективно — по явной команде пользователя в этом
обсуждении — из задокументированных источников: задач tasks/, журналов
DECISIONS/LESSONS, карты PROJECT.md и формулировок заказчика в сессиях.

## Контекст
- Шаблон и заполненный пример (HR-портал) переданы файлами; шаблон первичен,
  расхождения примера (название матрицы, потерянные поля) не переносим.
- Шаблон запрещает: выдумывать требования, разрешать неоднозначности
  предположением, объединять требования; обновление — только по команде.
- CLAUDE.md по решению пользователя не меняется.

## Критерии успеха
- [ ] harness/templates/REQUIREMENTS.md идентичен переданному шаблону
- [ ] harness/REQUIREMENTS.md: все карточки с полным набором полей,
      прослеживаемым источником; «Проверено» — только с заполненной проверкой
- [ ] Приоритеты «Не определён» (заказчик не приоритизировал в MoSCoW);
      критичность из слов заказчика — в комментарии аналитика
- [ ] Матрица трассировки сходится с карточками; «Реализует» доводит до BR
- [ ] Открытые вопросы и отложенные решения собраны в служебных разделах

## Открытые вопросы
- MoSCoW-приоритеты — **отложены**: проставляет заказчик при просмотре реестра.
