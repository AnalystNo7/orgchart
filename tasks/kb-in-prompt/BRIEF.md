# BRIEF: документы базы знаний в промпте + просмотр из приложения
Дата: 2026-08-22

## Формулировка своими словами
База знаний сейчас работает только как поиск по запросу (RAG): модель сама
решает, искать ли, и получает top-5 фрагментов. Заказчик хочет режим из
своего HR-проекта: флажком включать документ в постоянное участие в
генерации — полный текст в системном промпте каждого AI-запроса. Плюс
нужен просмотр загруженного документа прямо из приложения (что именно
видит модель).

## Контекст
- Полный извлечённый текст уже хранится в KnowledgeDocument.content —
  обе функции возможны без перезагрузки документов.
- Оригинальный бинарник (PDF/DOCX) не хранится — показываем текст.
- Жёсткий лимит шлюза: 65 536 байт на один текстовый блок; системный
  промпт — один блок, ~12-20 КБ уже заняты методической и технической
  частями. Бюджет документов: 45 000 байт (~22 тыс. русских символов).
- GET /api/knowledge/[id] уже отдаёт документ с текстом; PATCH нет.

## Критерии успеха
- [ ] Тумблер «В промпте» у документа; включение сверх бюджета —
      отказ с числами (занято/лимит/размер), а не молчаливая обрезка
- [ ] Счётчик занятости бюджета над списком (КБ из 44 КБ)
- [ ] Включённые документы попадают целиком в системный промпт;
      в [AI_RUN] видно «документы БЗ: N (X КБ)»
- [ ] Модель цитирует включённые документы с маркером 【KB: …】 →
      источник в подвале ответа
- [ ] Кнопка «Просмотр» — диалог с полным текстом документа
- [ ] RAG-поиск работает для всех документов независимо от флажка
- [ ] Запросы не падают на лимите 65536 даже при изменённой методичке
      (не влезающий документ пропускается целиком с записью в лог)

## Открытые вопросы
- Хранение оригинальных файлов для скачивания — **отложено**: миграция
  и рост БД ради вёрстки, которую модель не видит; вернёмся по запросу.
- Величина бюджета 45 000 байт — **отложено**: производная от лимита
  шлюза минус промпт; вынесена в константу, крутится без перепроектирования.
