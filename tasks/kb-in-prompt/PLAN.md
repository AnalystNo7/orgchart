# PLAN: документы БЗ в промпте

Дата: 2026-08-22

## Шаги
1. Схема: KnowledgeDocument.includeInPrompt Boolean @default(false);
   миграция add_knowledge_include_in_prompt; generate.
2. limits.ts: AI_KB_PROMPT_BUDGET_BYTES = 45 000.
3. system-prompt.ts / getSystemPrompt: второй запрос включённых документов,
   блок «Активные документы базы знаний» между методической и технической
   частями; защита при сборке — не влезающий документ пропускается целиком
   с [AI_KB]-логом; kbDocs {count, bytes} в ResolvedSystemPrompt.
4. orchestrator.ts: «документы БЗ: N (X КБ)» в [AI_RUN].
5. API: PATCH /api/knowledge/[id] {includeInPrompt} с проверкой бюджета
   на включении (400 с числами); GET-список += includeInPrompt, contentBytes.
6. /knowledge: тумблер, счётчик бюджета с прогресс-полосой, кнопка
   «Просмотр» с диалогом полного текста, поясняющая подпись.
7. PROJECT.md; tsc + build + migrate dev; сценарии из BRIEF.

## Альтернативы
- **Документы отдельными сообщениями** (обход лимита на блок): отвергнута —
  раздувает вход каждого шага и время ответа; заказчик выбрал жёсткий бюджет.
- **Молчаливая обрезка** (как 150 000 в HR-проекте): отвергнута заказчиком —
  модель видела бы пол-документа, не зная об этом.
- **Единый флажок и для RAG**: отвергнута заказчиком — поиск для всех.

## Риски
- 🟡 Кастомная методичка + документы могут вместе превысить 65 536 →
  следим: защита при сборке пропускает документы с логом; смоук в верификации.
- 🟡 Большой документ во «Просмотре» подвесит диалог → следим: текст в
  прокручиваемом блоке, документы ограничены бюджетом загрузки страницы.
- 🟢 Флаг по умолчанию false — поведение существующих инсталляций не меняется
  до явного включения.

## Бюджет
- Файлов: 6 изменяемых + 1 миграция + 2 документа задачи / Время: ~1.5 ч
