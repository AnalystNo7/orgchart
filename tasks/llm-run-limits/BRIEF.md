# BRIEF: лимиты AI-прогона в настройках пресета LLM
Дата: 2026-08-21

## Формулировка своими словами
Пользователь хочет крутить лимиты прогона из админки, без правки кода:
максимум шагов, таймаут одного шага, таймаут тишины стрима и бюджет
контекста за прогон. Сейчас они зашиты константами в limits.ts, а в пресете
настраиваются только общий таймаут и лимит одного результата инструмента.
Бюджет контекста (120 КБ) — величина эмпирическая («подбирается по факту»,
tasks/ai-context-budget/BRIEF.md:51), что само по себе аргумент крутить её
без редеплоя.

## Контекст
- Паттерн «пусто = системный дефолт» уже отработан на toolResultMaxBytes
  по всей цепочке: schema → zod → DTO → API → provider → форма.
- Сегодняшние обрывы пользователя — по ОБЩЕМУ бюджету: timeoutSec в
  активном пресете, судя по сообщениям, всё ещё 300 (поле уже есть,
  потолок 3600) — напомнить поднять.
- Лимиты принадлежат связке модель+шлюз: MiniMax думает минутами,
  DeepSeek быстрый, но шлюз рвёт поток — поэтому per-preset, не глобально.

## Критерии успеха
- [ ] Пресет с пустыми новыми полями ведёт себя как раньше (30/600/120/120000)
- [ ] Заполненные поля видны в [AI_RUN] и meta.budget и реально применяются:
      предел шагов, таймаут шага, детект тишины, отказ context_budget_exhausted
      с фактическим числом
- [ ] Пусто = дефолт, подстрочники называют дефолтные значения
- [ ] env-fallback живёт на дефолтах; активация и «Проверить подключение»
      не сломаны

## Открытые вопросы
- Границы валидации (1–100 шагов, 30–3600 с, 15–600 с, 20–2000 КБ) —
  **закрыт**: выбраны с запасом вокруг дефолтов, спорных случаев нет.
