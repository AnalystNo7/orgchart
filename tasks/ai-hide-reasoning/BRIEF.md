# BRIEF: скрыть рассуждения модели MiniMax в AI-чате
Дата: 2026-09-10

## Формулировка своими словами
Рабочая модель заказчика — MiniMax-M2.7 через Gonka (DeepSeek «виснет»). Она кладёт рассуждения прямо в текст ответа, открывая `<think>` и не закрывая его, поэтому сворачивание по закрытым парам (сделано вчера) не срабатывает, и пользователь читает англоязычный черновик. Прошлая попытка спрятать рассуждения на сервере (`e10b800`) ждала `</think>` и спрятала весь ответ, откатили (`084980d`). Нужно скрыть рассуждения **полностью** (не показывать и не сохранять), при этом гарантированно не потерять ответ: границу задаём сами маркером в промпте, планирующие шаги отбрасываем по структуре tool-цикла, а при отсутствии границы к концу ответа показываем всё. Заодно дать диагностику сырого формата шлюза одним флагом, чтобы проверить, нет ли у Gonka отдельного поля для рассуждений.

## Контекст
- `src/lib/ai/orchestrator.ts:390-404`: дельты берутся из `result.textStream` → `createToolNameFilter` → `onText`; `partialText` = всё, что показано; сохраняется в диалог и уходит в историю следующего запроса.
- `src/components/ai-chat/think-split.ts` + `ChatMessage.tsx`: закрытые пары сворачиваются, незакрытый `<think>` показывается маркером «💭 Размышляю…».
- `git show e10b800:src/lib/ai/think-filter.ts`: готовый потоковый фильтр с удержанием хвоста тега (`heldPrefix`), лентами `text`/`reasoning`, `flush()`; провален только сценарий «нет `</think>`» — его и закрываем маркером и структурой.
- AI SDK 6.0.193: `result.fullStream` отдаёт части `start-step`, `text-delta`, `tool-call`, `finish-step` (с `finishReason: "tool-calls" | "stop" | …`), `raw` (при `includeRawChunks: true`), `error`, `abort` — граница шага и признак «шаг закончился инструментами» приходят в том же порядке, что и текст (`node_modules/ai/dist/index.d.ts:2603-2607, 2818`). Провайдер `@ai-sdk/openai` `.chat()` поля `reasoning_content` не разбирает (grep по `dist/index.mjs`: только `reasoning_tokens`), `@ai-sdk/openai-compatible` не установлен.
- Стиль ответа в промпте уже требует «одна фраза статуса → результаты» (`system-prompt.ts`, техническая половина).
- Решения заказчика: подход «маркер + структура + диагностика»; рассуждения скрыть полностью; в историю диалога — без рассуждений.

## Критерии успеха
- [ ] При потоке `<think>…черновик…\n### Ответ\nитог` пользователь видит только «итог», без маркера и без черновика; в статусе на время черновика «Модель рассуждает…» с таймером; в `[AI_REASONING]` лог «шаг N: скрыто K символов, граница: маркер».
- [ ] Шаг, закончившийся вызовом инструментов, с текстом `<think>план…` без маркера: текст не показан и не сохранён; лог «граница: инструменты, отброшено K».
- [ ] Финальный шаг без маркера и без `</think>`: весь текст показан (как сегодня, с маркером «💭 Размышляю…»), лог «граница не найдена, раскрыто K». Ответ не теряется ни в одном случае.
- [ ] Маркер, разрезанный границей дельт («### От» + «вет\n»), и тег («<thi» + «nk>») распознаются; `<b>` и `#` в обычном тексте не задерживаются дольше одного шага.
- [ ] Сохранённый диалог и история следующего запроса не содержат рассуждений и маркера.
- [ ] `AI_DEBUG_RAW_CHUNKS=N` в `.env` печатает первые N сырых чанков каждого шага в `[AI_RAW]` (обрезка 600 символов); без флага поведение и стоимость не меняются.
- [ ] Тесты: фильтр (≥ 12 кейсов), мок-режимы `think_marker`, `think_nomarker`, `think_tool_step` в `retry-test.ts`; регресс 45 + 14 + 20 + 9; `tsc` без новых ошибок; `next build`.

## Открытые вопросы
- Соблюдает ли MiniMax маркер `### Ответ` стабильно — **отложен до живого прогона**; при нарушении срабатывает страховка (показать всё), а по `[AI_REASONING]` видно долю прогонов без маркера. Если доля высокая — вариант «эвристика заголовка/таблицы» как второй триггер (отвергнут сейчас, см. PLAN).
- Есть ли у Gonka отдельное поле рассуждений — **отложен до диагностики** `[AI_RAW]`; если есть, следующий шаг — провайдер `@ai-sdk/openai-compatible` вместо фильтра.
- Старые диалоги с закрытыми парами `<think>…</think>` в БД — **решено**: сворачиваемый блок из вчерашней задачи остаётся только для них (новые ответы рассуждений не содержат).
