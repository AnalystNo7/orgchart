# BRIEF: Админ-настройки LLM-подключений (/admin/llm)
Дата: 2026-08-19

## Формулировка своими словами
Дать админу возможность управлять подключением к LLM из UI, а не через env:
именованные пресеты (провайдер, base URL, ключ, модель, температура, лимит
ответа, таймаут) хранятся в БД; один пресет «активный» и применяется ко всем
LLM-вызовам приложения сразу, без редеплоя. Ключи наружу не отдаются — только
маска. Кнопка «Проверить подключение» до сохранения. Подход перенесён из
другого проекта пользователя (панель 360-отчётов), но без механики «отчёт в
1–8 запросов» — она там нужна для длинных генераций, здесь таких нет.

## Контекст
- LLM-вызова в кодебазе ровно два: чат-ассистент (`src/lib/ai/orchestrator.ts`,
  generateText + 33 инструмента) и автогенерация gap-анализа
  (`src/app/api/gaps/auto-generate/route.ts`, temperature 0.3).
- Фабрика `getModel()` (`src/lib/ai/provider.ts`) читает env на каждый запрос,
  кэша нет → пресет из БД подхватится мгновенно.
- Каверза: OpenAI-совместимые шлюзы требуют `createOpenAI({baseURL}).chat(id)`;
  `ai@6` поддерживает `maxOutputTokens` и `timeout` (число, мс) нативно.
- Админ-паттерн уже есть: `/admin/users` + `requireAdmin()` (копипаста в двух
  роутах — выносим в `src/lib/auth.ts`).
- Эмбеддинги Voyage — отдельный контур, не трогаем.

## Критерии успеха
- [ ] Пресет CRUD на /admin/llm (только для isAdmin), ключи в ответах API — только маской
- [ ] «Сделать активной» переключает все LLM-вызовы без рестарта процесса
- [ ] Без активного пресета поведение бит-в-бит как раньше (env-fallback)
- [ ] «Проверить подключение» возвращает ok+latency или русскую ошибку
- [ ] Работает против OpenAI-совместимого шлюза (Gonka и т.п.) через .chat()
- [ ] tsc --noEmit не даёт новых ошибок

## Открытые вопросы
Все закрыты пользователем 2026-08-19: скоуп = все LLM-вызовы; тип провайдера
в пресете (openai_compatible|anthropic|openai|google); механика «1–8 запросов»
не переносится; ключи plaintext + маска.
