# BRIEF: редактируемый системный промпт в админке
Дата: 2026-08-21

## Формулировка своими словами
Системный промпт AI-ассистента зашит в коде — чтобы поправить методологию
ответа, нужен деплой. Нужно окно в админке по образцу другого проекта
пользователя: textarea, «Сохранить», «Сбросить к стандартному», бейдж
«Изменён», ссылка на технический промпт. Пункт меню «Настройки LLM»
переименовывается в «Настройки» и получает подвкладки «LLM» и
«Системный промт».

## Контекст
- Промпт: `src/lib/ai/system-prompt.ts`, `buildSystemPrompt(scenarioName)`,
  единственный потребитель — `orchestrator.runChat`.
- В промпте две породы секций: методические (роль, ориентиры, категории,
  правила) и технические (маркировка 【…】, порядок работы с оргструктурой,
  усечённые результаты) — вторые только что настроены под таймауты,
  их правка из окна молча ломает маршрутизацию инструментов.
- Готовые паттерны: вкладки `src/app/references/layout.tsx`, admin-API
  `src/app/api/admin/llm/route.ts`, фолбэк при недоступной таблице `getLlm()`.

## Критерии успеха
- [ ] `/admin/settings/prompt`: правка текста применяется к следующему
      `!ai`-запросу без редеплоя; в `[AI_RUN]` видно «промпт изменён»
- [ ] Технические секции присутствуют в отправляемом промпте всегда,
      независимо от правок пользователя
- [ ] «Сбросить к стандартному» возвращает дефолт из кода, бейдж гаснет
- [ ] `{{scenario_name}}` подставляется именем текущего сценария
- [ ] `/admin/llm` редиректит на `/admin/settings/llm`, пресеты работают
- [ ] До применения миграции чат работает на стандартном промпте (фолбэк)
