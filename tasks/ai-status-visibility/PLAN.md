# PLAN: живой статус AI-запроса

Дата: 2026-08-21

## Шаги
1. `orchestrator.ts` — `RunMeta` + `onMeta` в StreamCallbacks; budget при
   старте, step_start в onStepStart; после стрима ветвление по finishReason:
   stop → onDone, иначе → onError(finishMessage(reason), partial) +
   `[AI_INCOMPLETE]` в лог.
2. `route.ts` — `onMeta: (m) => send("meta", m)`.
3. `ai-store.ts` — budgetMs, maxSteps, currentStep, stepStartedAt + reset.
4. `AiChatPanel.tsx` — ветка `event === "meta"`, прокинуть пропсы.
5. `StreamingStatus.tsx` — строка шага с таймером, «X / бюджет» с цветами
   80/95%, текст при потере heartbeat (порог 10 → 15 с).
6. `PROJECT.md`; tsc + build; прогоны из BRIEF.

## Альтернативы
- **Метаданные через канал `status`**: отвергнута — data.phase кастуется в
  StreamingPhase; служебные значения загрязняют enum и ломают отображение фазы.
- **Прогресс-бар бюджета**: отвергнута — цифры с цветовым порогом дают то же
  без новой геометрии в узкой панели.
- **Авто-обрыв при потере heartbeat**: отвергнута — сервер может дописать
  ответ после паузы; решение за человеком, кнопка «Отмена» уже есть.

## Риски
- 🟡 finishReason "tool-calls" может оказаться и легальным концом при
  ровно-30 шагах → следим: сообщение честно называет предел шагов, данные
  не теряются.
- 🟡 Неизвестные будущие значения finishReason → следим: default-ветка
  оформляет их как обрыв с текстом причины как есть.
- 🟢 Новое SSE-событие meta игнорируется старыми клиентами молча.
