# BRIEF: живой статус AI-запроса и честный финал при обрыве стрима
Дата: 2026-08-21

## Формулировка своими словами
Долгий reasoning-шаг (254 с) в индикаторе неотличим от зависания: нет номера
шага, таймера шага и бюджета. Хуже того — таймаут стрима завершается «тихо»
(finish: other, без исключения), и код принимал его за успех: оборванный на
полуслове ответ выглядел законченным, диалог сохранялся без признака обрыва.
Нужно: показывать шаг/таймер/бюджет во время работы, оформлять finish ≠ stop
как честный обрыв с причиной, а потерю heartbeat — текстом, не только точкой.

## Контекст
- Лог-доказательство: `[AI_RUN] … total 300.0s`, `[AI_STEP_START] #2 +46.3s`,
  `[AI_DONE] 1 шаг(ов) · 300.0s · finish: other` — бюджет истёк на шаге 2,
  но пометки обрыва не было (onDone вместо onError).
- UI-инфраструктура уже есть: `StreamingStatus.tsx` (фаза, общий таймер,
  heartbeat-точка, лог инструментов, «Отмена»), SSE-события в `AiChatPanel`.
- Путь честного обрыва уже есть (`onError` + `buildAbortNote` +
  `saveConversation`, коммит 0a034b4) — надо направить в него тихие финалы.
- Пресет всё ещё timeoutSec=300 — поднять до 1800 руками в UI (не код).

## Критерии успеха
- [ ] Во время шага видно «Шаг N из ≤30», таймер текущего шага и «X / бюджет»
- [ ] Таймер меняет цвет при 80% и 95% бюджета
- [ ] finish ≠ stop → пометка с причиной (таймаут / лимит токенов / предел
      шагов), диалог сохранён с aborted, в логе `[AI_INCOMPLETE]`
- [ ] При тишине heartbeat >15 с — текст «Соединение потеряно…», не только точка
- [ ] Регресс: обычный запрос, локальные запросы, «Отмена» работают

## Открытые вопросы
- Порог цветов бюджета (80/95%) — **закрыт**: выбран по аналогии с
  серверным предупреждением за минуту до конца.
- Авто-обрыв на клиенте при потере heartbeat — **отложен**: сервер может
  дописать после сетевой паузы, отмена остаётся за человеком.
