# OrgChart — Известные ограничения

| # | Ограничение | Затронутый модуль | Устранение |
|---|-------------|-------------------|------------|
| 1 | **P&L не учитывает дженериков (вакантные позиции).** Модель расчёта P&L оперирует только текущими сотрудниками, оформленными в организации. Позиции-дженерики (штатные единицы без назначенного сотрудника, добавляемые на развитие) не участвуют в расчёте ФОТ и overhead. Это приводит к занижению расходов в сценариях to-be: реальные затраты после найма будут выше, а численность персонала — больше прогнозируемой. | Финансы (`calculate_pnl`), CEO Dashboard (OHI) | Post-MVP |
| 2 | **Очередь к LLM-провайдеру — в памяти одного процесса.** Лимит одновременных запросов (`maxConcurrentRuns` в «Настройки → LLM») и очередь ожидания действуют внутри одного экземпляра приложения. При нескольких инстансах (Vercel, несколько контейнеров) каждый считает слоты отдельно, и суммарная нагрузка на провайдера может превысить лимит — тогда сработают повторы с паузой. Для кластера нужен внешний брокер (Redis). | AI-чат (`src/lib/ai/run-queue.ts`) | При переходе на несколько инстансов |
| 3 | **Отменённый первый ход нового диалога сохраняется «вслепую».** При отмене запроса сервер сохраняет собранный текст с пометкой отмены, но событие `conversation_id` до клиента уже не доходит: панель не знает id нового диалога, и следующее сообщение откроет ещё один диалог. Для существующего диалога всё сохраняется в него. | AI-чат (`src/app/api/ai/chat/route.ts`, `onAbort`) | Post-MVP: при отмене клиент может запросить последний диалог сценария |
