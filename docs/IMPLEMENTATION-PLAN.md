# План реализации концепции «AI Цифровой двойник организации»

Версия: 1.0 · База: ветка `dev-mvp4` (состояние на 2026-09-08) · Концепция: `docs/CONCEPT-DIGITAL-TWIN.md`

## 1. Зачем этот документ

Концепция описывает семь архитектурных слоёв предприятия, восемь функциональных модулей, индекс здоровья организации (OHI) и AI-консультанта. В `dev-mvp4` уже закрыты восемь спринтов (`docs/IMPLEMENTATION-STATUS.md`): модели и инструменты для стратегии, компетенций, процессов, финансов, клиентов и проактивных инсайтов существуют. Этот план отвечает на два вопроса заказчика:

1. **Что делать дальше и в каком порядке**, чтобы каждая единица функциональности была проверяема за 1–2 дня.
2. **Какие данные компания должна предоставить**, чтобы анализ по каждому слою был возможен (раздел 6).

## 2. Ритм работы и правило приёмки

- Задача = **3 дня разработки + 1–2 дня проверки заказчиком**. Неделя — одна задача или две мелкие.
- У каждой задачи есть: **демо-сценарий** (шаги в UI или вопрос в AI-чат), **критерий приёмки** (измеримый) и **код данных** из раздела 6.
- Задача не закрыта без подписи проверяющего. Проверка занимает не больше 2 часов его времени.
- Сбор данных стартует **за 3 недели** до фазы, которой они нужны. Без минимального набора данных задача принимается на синтетике условно, замечания идут в бэклог.
- После каждой фазы — контрольная точка (1 день): регрессия, демо целевой роли, замер токенов и времени ответа.

| 3. Компетенции | Competency, RoleCompetency, EmployeeCompetency, `analyze_skill_gaps` | UI профилей должностей, talent-данные и 9-box, рыночные ставки, `plan_hiring`, `recommend_reskilling`, симуляция ухода, преемственность, импорт |
| 1. Стратегия | Goal, GoalKpi, связи с подразделениями, `analyze_strategy`, страница `/strategy` | вычисляемые KPI, инициативы, конфликты целей, импорт |
| OHI и дашборд | `calculateOhi` (7 компонентов, live), `generate_board_report` (markdown), AIInsight через `run_health_check` | снимки и тренд OHI, бенчмарки из `/benchmarks` вместо констант в коде, планировщик и дайджест, PDF |
| 6. Клиенты | Client, PipelineDeal, `analyze_portfolio`, `get_pipeline` | NPS/CSI, требования сделок к компетенциям, capacity-matching, прогноз выручки на 12 месяцев, импорт |
| 7. Технологии | нет | всё |
| Интеграция слоёв | база знаний (RAG), экспорт markdown для внешнего анализа | cross-layer impact в what-if, генератор roadmap, контроль размера промпта при 33+ инструментах |
| Надёжность AI-чата | пресеты LLM, таймауты, бюджет контекста, **настраиваемые повторы и очередь к провайдеру** (задача 0.3, выполнена) | автопереключение провайдера при исчерпании лимита, счётчик стоимости по пользователям |

**Главный разрыв.** Импорт данных существует только для сотрудников и подразделений. Остальные слои заполняются вручную через UI, что для компании 500–2000 человек нереалистично. Поэтому Фаза 1 целиком посвящена загрузке данных.

### Правила предоставления данных

1. **Конфиденциальность.** D13–D15 (оценки, talent-данные, зарплаты) передаются только по защищённому каналу и доступны по ролям (задача 0.5). Допустима псевдонимизация ФИО на стороне компании с таблицей соответствия.
2. **Формат.** Excel по шаблону из `docs/templates/`. Импорт валидирует построчно и возвращает отчёт об ошибках; частично корректный файл загружается частично.
3. **Актуальность.** D1–D3 обновляются ежемесячно (это baseline-сценарий). Остальные — при изменении.
4. **Неполнота допустима.** AI работает с тем, что есть, и явно пишет «данные по X отсутствуют». Для приёмки задачи нужен минимальный набор её кода данных.

## 7. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Данные не готовы к сроку фазы | высокая | сбор за 3 недели; синтетический набор для разработки; приёмка только на реальных данных |
| Качество данных (дубли, пропуски) | высокая | построчная валидация и отчёт; цикл исправлений в задачах 0.1–0.2 и 1.x |
| Лимиты и стоимость LLM (слоты Gonka, 429, месячный лимит) | средняя | повторы и очередь (задача 0.3); отдельный пресет с дешёвой моделью для простых операций; счётчик токенов в логе `[AI_DONE]` |
| Переполнение контекста при 33+ инструментах | средняя | задача 8.4; бюджет контекста (`runContextBudgetBytes`) уже есть |
| Конфиденциальность talent-данных и зарплат | высокая | задача 0.5 до Фазы 4; псевдонимизация; локальная модель через провайдер `openai_compatible` (vLLM, Ollama) уже поддерживается |
| Заказчик не успевает проверять за 1–2 дня | средняя | письменный демо-сценарий не длиннее 2 часов работы проверяющего; условная приёмка с бэклогом |
