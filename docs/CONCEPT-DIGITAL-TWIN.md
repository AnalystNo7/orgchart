# Концепция: Цифровой двойник организации — AI-платформа управления изменениями

## Контекст

ЦПС — ИТ-интегратор крупнейшей нефтегазовой компании, 500–2000 сотрудников. На базе существующего OrgChart Modeler проектируется расширение до AI-платформы «Цифровой двойник организации». Платформа использует LLM для анализа текущего состояния организации, выработки рекомендаций по целевой архитектуре и управления организационными изменениями.

### Уже реализовано в OrgChart Modeler
- Оргструктура (подразделения, сотрудники, категории, FTE)
- Сценарное моделирование (клонирование, сравнение)
- Справочники: тарифы (K-1..K-6), договоры (доходные/расходные)
- P&L-движок с тепловой картой
- Undo/redo, импорт/экспорт Excel

### Что добавляется
- AI-движок (LLM) для анализа, рекомендаций и gap-анализа
- Новые сущности: процессы, НМА, портфель проектов, стратегия
- Паспортизация разрывов и план организационных изменений (волны)
- Версионирование архитектуры
- RAG-система для работы с базой знаний и бенчмарками

### 1.2 Принцип разделения данных (гибридный подход)

| Данные | LLM | Обоснование |
|---|---|---|
| Оргструктура (анонимизированная) | Внешняя (Claude) | Для качественного анализа нужна мощная модель |
| ФИО, зарплаты, costRate | Локальная | Персональные данные |
| Стратегия (обобщённые цели) | Внешняя | Для сопоставления с бенчмарками |
| Финансовые данные (суммы договоров) | Локальная | Коммерческая тайна |
| Бенчмарки, модели, best practices | Внешняя | Общие знания |
| Содержание НМА (документы) | Локальная | Конфиденциальные документы |

**Механизм**: AI Orchestrator перед отправкой запроса во внешнюю LLM:
1. Анонимизирует персональные данные (заменяет ФИО на «Сотрудник #N»)
2. Маскирует финансовые суммы (нормализует или убирает)
3. Передаёт структурные данные (иерархия, типы, FTE, категории)
4. Ответ LLM обратно деанонимизируется для отображения

### 1.3 AI-инструменты (Tool Use)

LLM вызывает структурированные инструменты через tool use:

| Инструмент | Описание | Пример вызова |

| `create_gap_report` | Сформировать gap-анализ | `{asIsScenarioId, toBeScenarioId}` |
| `create_department` | Создать подразделение | `{name, type, parentId}` |
| `move_employees` | Переместить сотрудников | `{employeeIds, targetDeptId}` |
| `create_gap_passport` | Создать паспорт разрыва | `{type, description, priority}` |

## 3. Функциональные требования

### 3.1 FR: AI-чат с контекстными действиями (MVP)

**Интерфейс**: Гибрид — чат-панель + контекстные кнопки.

**Чат-панель** (правая боковая панель, аналогично PnlDrillDown):
- Свободный ввод вопросов на русском языке
- Стриминг ответов LLM
- История диалогов с возможностью продолжения
- Контекстные подсказки-кнопки (quick actions):
  - «Проанализировать текущую структуру»
  - «Предложить целевую структуру»
  - «Найти разрывы»
  - «Сформировать план изменений»
  - «Оценить ресурсную обеспеченность»

**Контекстные кнопки** (в интерфейсе рядом с данными):
- На странице оргструктуры: «AI: Анализ подразделения», «AI: Рекомендации»
- На странице процессов: «AI: Оптимизация процесса»
- На странице gap-анализа: «AI: Детализировать разрыв»

**Режимы LLM-ответов**:
1. **Только рекомендации**: текстовый ответ с анализом и предложениями
2. **Применение с подтверждением**: LLM формирует набор действий → пользователь видит превью → нажимает «Применить»
3. **Автоматическое применение**: LLM сразу выполняет действия (только для разрешённых пользователем операций)

### 3.2 FR: Анализ «как есть» (MVP)

LLM анализирует текущее состояние организации на основе загруженных данных:

**Входные данные** (из существующей + новой модели):
- Оргструктура сценария (подразделения, сотрудники, FTE, категории)
- P&L по подразделениям
- Договоры и привязки
- Процессы (если загружены)
- Портфель проектов (если загружен)

**Выходы**:
- Оценка эффективности структуры: span of control, overhead ratio, FTE по категориям
- Выявление проблем: дублирование функций, перегруженные подразделения, вакантные роли
- Сравнение с отраслевыми бенчмарками (ИТ-интеграторы, нефтегаз)
- Рекомендации по оптимизации

**Пример диалога**:
```
Пользователь: Проанализируй текущую оргструктуру
AI: Анализ оргструктуры «Текущее состояние» (47 сотрудников, 18 подразделений):

📊 Ключевые метрики:
• Span of control: среднее 4.2 (норма для ИТ: 5-8) — избыточное число руководителей
• Overhead ratio: 34% AUP (норма: 15-25%) — высокая доля управленцев
• Производственный блок: 3 уровня вложенности для 20 сотрудников — можно упростить

⚠️ Проблемы:
1. Участки №1-А и №1-Б (всего 5 чел.) могут быть объединены
2. Сервисная служба (SERVICE) содержит АХО — типично для BACKOFFICE
3. Отдел охраны труда (1 чел.) — рассмотреть присоединение к HR

💡 Рекомендации:
[Применить как сценарий «Оптимизация v1»]
```

### 3.3 FR: Построение целевого состояния (to-be)

LLM предлагает целевую архитектуру на основе:
- Стратегических целей (загруженных через документы или формы)
- Портфеля проектов
- Бенчмарков отрасли
- Выбранной управленческой модели

**Процесс**:
1. Пользователь загружает/вводит стратегические цели
2. LLM запрашивает уточнения (через чат)
3. LLM формирует рекомендации — **два режима вывода**:
   - **Текстовый план**: описание предлагаемых изменений с обоснованием, пользователь применяет выборочно кнопкой «Применить»
   - **Новый сценарий**: LLM создаёт полноценный сценарий (клон текущего с изменениями) одной кнопкой «Создать сценарий to-be»
4. Пользователь ревьюит и корректирует
5. Результат — зафиксированный сценарий «to-be»

### 3.3.1 FR: What-if моделирование (ключевая фича)

Пользователь задаёт гипотетические вопросы в чате, LLM моделирует последствия:

**Примеры запросов**:
- «Что будет, если объединить Цех №1 и Цех №2?»
- «Как изменится P&L, если сократить AUP на 20%?»
- «Если мы возьмём 3 новых проекта, хватит ли ресурсов?»

**Механика**:
1. LLM создаёт временный (sandbox) сценарий — клон текущего
2. Применяет запрошенные изменения через tool use
3. Запускает пересчёт P&L через существующий `pnl-calculator.ts`
4. Сравнивает метрики до/после
5. Отображает diff: таблица было/стало, визуальное сравнение
6. Пользователь может: «Сохранить как сценарий» или «Отменить»

**Связь с существующим функционалом**:
- Использует `calculatePnl()` из `src/lib/pnl-calculator.ts`
- Использует клонирование сценария из `src/app/api/scenarios/[id]/clone/route.ts`
- Использует сравнение из `src/app/compare/`

### 3.4 FR: Gap-анализ с паспортизацией (MVP)

**Визуальное сравнение**: наложение as-is и to-be на одной схеме:
- Зелёные узлы: новые подразделения в to-be
- Красные: удалённые подразделения
- Жёлтые: изменённые (переименованные, перемещённые, изменён состав)
- Серые: без изменений
- Реализация поверх существующего ReactFlow + функции сравнения сценариев

**Паспорт разрыва** (структурированная карточка):
- Категория: Структура / Процессы / Ресурсы / Компетенции / Технологии
- Приоритет: Критический / Высокий / Средний / Низкий
- Описание: что есть vs что должно быть
- Влияние: на какие цели/KPI влияет
- Затронутые объекты: подразделения, процессы, проекты
- Ответственный
- Оценка трудозатрат
- Статус: Выявлен → В работе → Устранён / Отложен
- Флаг «создано AI» + обоснование AI

### 3.5 FR: План организационных изменений (волны)

**Структура**: Волна → Мероприятия → Связь с разрывами

```
Волна 1: «Структурная оптимизация» (Q1-Q2 2026)
├── Объединить Участок №1-А и №1-Б → Разрыв #3
├── Перенести АХО из Сервисной службы в Бэк-офис → Разрыв #7
└── Интегрировать ОТ в HR-блок → Разрыв #5

Волна 2: «Развитие компетенций» (Q3-Q4 2026)
├── Создать подразделение DevOps → Разрыв #1
├── Нанять 5 инженеров ML → Разрыв #2
└── Запустить программу обучения → Разрыв #4
```

**Визуализация**: timeline волн с привязкой к разрывам.

LLM предлагает оптимальную последовательность волн на основе:
- Приоритетов разрывов
- Зависимостей между мероприятиями
- Ресурсных ограничений
- Минимизации disruption

### 3.6 FR: Дерево процессов

**Модель**: иерархическое дерево с атрибутами (не BPMN).

- Уровни: Стратегические → Основные → Поддерживающие
- Атрибуты узла: владелец (подразделение), участники, KPI, статус
- Связь с оргструктурой: процесс → подразделение-владелец + подразделения-участники
- Визуализация: дерево (аналогично оргструктуре, в ReactFlow)
- AI-анализ: выявление процессов без владельца, дублирование, несоответствие структуре

### 3.7 FR: Портфель проектов

- Реестр проектов с типом (внутренний/внешний/продуктовый), статусом, периодом
- Связь с подразделениями (ответственные), сотрудниками (назначенные), договорами
- Требуемые FTE и компетенции
- AI-анализ: ресурсная обеспеченность портфеля, рекомендации по оргструктуре под портфель

### 3.8 FR: Реестр НМА

- Справочник нематериальных активов: ПО, патенты, лицензии, методологии
- Метаданные + связи с подразделениями, процессами, проектами
- Без анализа содержимого документов в MVP

### 3.9 FR: Стратегия (ввод целей)

- Два способа ввода:
  1. **Загрузка документа** (Word/PDF/PPT): LLM извлекает цели, KPI, приоритеты → пользователь проверяет/корректирует
  2. **Ручной ввод**: формы для целей (название, тип, описание, KPI, приоритет)
- Цели привязываются к сценарию
- LLM использует цели как основу для рекомендаций по to-be

### 3.10 FR: Версионирование архитектуры

- Создание снимков (snapshot) текущего состояния сценария
- Список версий с описанием изменений
- Сравнение версий (diff)
- При изменении входных данных — автоматический пересчёт разрывов
- Уведомление пользователя о влиянии изменений на план

### 3.11 FR: Генерация отчётов

Система формирует отчёты и презентации на основе данных и результатов AI-анализа.

**Типы отчётов**:

| Отчёт | Формат | Содержание |
|---|---|---|
| Анализ оргструктуры | PDF, PPTX | Метрики, проблемы, сравнение с бенчмарками |
| Gap-анализ | PDF, PPTX | Паспорта разрывов, визуальный diff as-is/to-be |
| План изменений | PDF, PPTX | Волны, мероприятия, timeline |
| P&L по подразделениям | PDF, Excel | Тепловая карта, drill-down |
| What-if сравнение | PDF | Было/стало, дельты метрик |
| Сводный отчёт для руководства | PPTX | Все разделы в executive summary |

**Механика генерации**:
1. Пользователь выбирает тип отчёта или пишет в чат: «Сформируй отчёт по gap-анализу»
2. LLM генерирует текстовый контент (выводы, рекомендации, описания)
3. Движок отчётов собирает структурированные данные (таблицы, графики)
4. Формируется документ в выбранном формате
5. Пользователь скачивает файл

**Технологии**:
- PDF: puppeteer или react-pdf
- PPTX: pptxgenjs
- Excel: xlsx (уже используется)

### 3.12 FR: RAG — база знаний

- Курируемая база знаний:
  - Управленческие модели (McKinsey 7S, Минцберг, Galbraith Star, Kotter и др.)
  - Отраслевые бенчмарки ИТ-интеграторов
  - Лучшие практики организационного дизайна
  - Нормативы (span of control, overhead ratio, FTE нормы)
- Формат: markdown-документы → embeddings → vector store
- LLM использует RAG для обоснования рекомендаций ссылками на конкретные практики

## 6. Технические решения

### 6.1 LLM-интеграция

**Внешняя LLM (Фаза 1)**:
- Anthropic Claude API (claude-sonnet-4-20250514 для MVP)
- Tool use для структурированных действий
- Стриминг ответов через SSE

**Локальная LLM (Фаза 3)**:
- Ollama + модель (Qwen2.5 72B или аналог)
- Для обработки чувствительных данных
- Роутинг: AI Orchestrator определяет, какие данные куда отправлять

### 6.2 RAG

- Embeddings: `text-embedding-3-small` (OpenAI) или `nomic-embed-text` (локально)
- Vector store: pgvector (расширение PostgreSQL — совместимо с текущей БД)
- Chunking: markdown-документы → фрагменты 500-1000 токенов
- Retrieval: top-K similarity search с порогом

### 6.3 Анонимизация данных

- Маппинг-таблица (in-memory): `{ФИО → «Сотрудник #N»}`
- Финансовые данные: нормализация (коэффициенты вместо абсолютных сумм)
- Обратное преобразование при рендеринге ответа

## Шаг 1.5: P&L-калькулятор и справочники

### 1.5.1 Файл: `src/lib/pnl-calculator.ts`
P&L-движок — расчёт финансовых метрик по подразделениям:
- Расчёт себестоимости подразделения = sum(сотрудники * FTE * costRate по тарифу)
- Расчёт дохода = sum(доходные договоры привязанные к подразделению)
- Расчёт расхода = sum(расходные договоры) + себестоимость сотрудников
- Маржинальность = (доход - расход) / доход
- Агрегация по иерархии (рекурсивная)
- Тепловая карта: нормализация маржинальности → цвет (от красного к зелёному)

## Шаг 6: What-if моделирование

Реализуется через AI-чат + существующий функционал:

1. Пользователь задаёт вопрос в чате: «Что будет, если объединить Цех №1 и Цех №2?»
2. LLM через tool use:
   - Вызывает `clone_scenario` (существующий API `/api/scenarios/[id]/clone`)
   - Применяет изменения (`move_employees`, `delete_department`, и т.д.)
   - Вызывает `get_org_metrics` для нового сценария
   - Вызывает `compare_scenarios` для diff
3. LLM формирует ответ с метриками до/после
4. Пользователь видит кнопку «Сохранить как сценарий» или сценарий автоматически удаляется

### Файл: `src/lib/ai/tools.ts` — дополнение
Tool `create_whatif_scenario`:
- Клонирует текущий сценарий с именем «What-if: [описание]»
- Помечает как DRAFT
- Возвращает ID нового сценария для дальнейших манипуляций

## Верификация

### Тестирование вручную
1. **AI-чат**: Открыть AI-панель → написать «Проанализируй текущую оргструктуру» → получить ответ с метриками
2. **Tool use**: Попросить AI «Создай новое подразделение DevOps» → увидеть tool call → подтвердить → увидеть новое подразделение на схеме
3. **What-if**: Написать «Что будет, если объединить подразделения X и Y?» → получить diff-анализ
4. **Gap-анализ**: Перейти на `/gap-analysis` → выбрать два сценария → увидеть diff → нажать «AI: найти разрывы» → увидеть сгенерированные паспорта
5. **CRUD паспортов**: Создать паспорт разрыва вручную, отредактировать, удалить
