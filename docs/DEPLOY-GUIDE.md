# Деплой OrgChart на VPS через Dokploy

Инструкция написана под текущий сервер и текущую конфигурацию репозитория.

| Параметр | Значение |
|---|---|
| Сервер | `109.68.215.148` |
| Адрес приложения | `http://109.68.215.148:3001` |
| Панель Dokploy | `http://109.68.215.148:3000` |
| Ветка деплоя | `dev-mvp4` |
| Compose-файл | `./docker-compose.prod.yml` |
| База данных | PostgreSQL в том же compose, данные в volume `pgdata` |

> Приложение публикуется по HTTP без шифрования — так решено на текущем этапе.
> Пароли и cookie сессии идут открытым текстом. Переход на домен с HTTPS описан
> в конце (раздел «Переход на домен»), он занимает несколько минут.

## Перед деплоем: снять бэкап базы

На сервере данные уже есть, и деплой их не трогает — но снимок стоит иметь.

```bash
ssh root@109.68.215.148

# найти контейнер БД (в имени будет название compose-проекта и «db»)
docker ps --format '{{.Names}}\t{{.Image}}' | grep pgvector

# снять дамп (подставьте имя контейнера)
docker exec <имя_контейнера_db> pg_dump -U orgchart orgchart > /root/orgchart-backup-$(date +%F).sql
ls -lh /root/orgchart-backup-*.sql
```

Скачать дамп на свою машину:

```bash
scp root@109.68.215.148:/root/orgchart-backup-*.sql ./
```

## ⚠️ Пароль базы данных — самое частое место ошибки

`POSTGRES_PASSWORD` действует **только при первичном создании** тома с данными.
Если база уже развёрнута, а в Environment вы поставите новый `DB_PASSWORD`,
пароль в базе не изменится — приложение получит `password authentication failed`.

Варианты:

- **Оставить прежний пароль** — посмотреть его в Dokploy → ваш Compose → Environment
  (значение `DB_PASSWORD` из прошлой настройки) и указать его же.
- **Сменить пароль** — сначала в базе, потом в переменной:

```bash
docker exec -it <имя_контейнера_db> psql -U orgchart -d orgchart \
  -c "ALTER USER orgchart WITH PASSWORD 'новый_пароль';"
```
затем поставить тот же `новый_пароль` в `DB_PASSWORD` и передеплоить.

**Имя compose-проекта в Dokploy не переименовывайте** — том называется
`<имя_проекта>_pgdata`, при переименовании приложение увидит пустую базу.

## Настройка в Dokploy

### 1. Источник кода

Ваш Compose-сервис → вкладка **General** (или **Source**):

- **Repository**: `AnalystNo7/orgchart`
- **Branch**: `dev-mvp4`
- **Compose Path**: `./docker-compose.prod.yml`

### 2. Переменные окружения

Вкладка **Environment**:

```env
APP_PORT=3001
DB_PASSWORD=<пароль существующей базы — см. раздел выше>
NEXTAUTH_SECRET=<сгенерировать: openssl rand -base64 32>
NEXTAUTH_URL=http://109.68.215.148:3001
```

Необязательные:

```env
# Резервный путь для LLM. Основной — пресет в интерфейсе: /admin/settings/llm
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=...
GOOGLE_GENERATIVE_AI_API_KEY=...

# Нужен только базе знаний (эмбеддинги Voyage AI). Без него загрузка документов
# не индексируется, остальное приложение работает.
VOYAGE_API_KEY=...
```

Про обязательные:

- `NEXTAUTH_URL` должен **точно** совпадать с адресом в браузере, вместе с портом.
  Разойдётся — вход будет уводить на неверный хост.
- `NEXTAUTH_SECRET` менять после запуска не нужно: смена разлогинит всех.
- `DB_PASSWORD`, `NEXTAUTH_SECRET`, `NEXTAUTH_URL` теперь обязательны — если
  переменная пуста, compose остановится с внятной ошибкой, а не поднимет
  приложение с паролем по умолчанию.

### 3. Домен в UI Dokploy

Вкладку **Domains** оставьте пустой. Приложение публикует порт напрямую
(`3001:3000`), Traefik в этой схеме не участвует. Если там остались записи
от прошлой настройки — удалите, иначе получите два конкурирующих маршрута.

### 4. Открыть порт

```bash
ufw allow 3001/tcp    # если ufw включён
ufw status
```

У некоторых хостеров есть ещё внешний файрвол в панели управления — порт нужно
открыть и там.

### 5. Deploy

Нажать **Deploy** и смотреть логи (Deployments → последний деплой). Первая сборка
после смены Dockerfile-контекста — 3–7 минут.

Что происходит при старте: контейнер БД поднимается и проходит `pg_isready`,
только после этого стартует приложение, применяет `prisma migrate deploy`
(накатятся недостающие миграции, существующие данные не трогаются) и запускает сервер.

## Проверка после деплоя

```bash
# с любой машины
curl http://109.68.215.148:3001/api/health
# ожидаемо: {"status":"ok","db":"ok"}
```

Если `{"status":"degraded","db":"unavailable"}` — приложение живо, но не видит базу:
смотрите пароль (раздел выше) и логи контейнера БД.

На сервере:

```bash
docker ps --format '{{.Names}}\t{{.Status}}'   # оба контейнера healthy
ss -ltnp | grep 3001                            # порт слушается
docker logs --tail 100 <имя_контейнера_app>
```

Затем открыть `http://109.68.215.148:3001` и войти.

## Сид — только для пустой базы

На работающем сервере **запускать не нужно**: данные уже есть.

Команда для чистой установки (создаёт админа `admin@orgchart.local` / `admin123`,
тарифы К-1…К-6 и демо-сценарий; идемпотентна — существующее не перезатирает):

```bash
docker exec -it <имя_контейнера_app> npx prisma db seed
```

После первого входа сразу смените пароль администратора.

## Обновление приложения

```bash
git push origin dev-mvp4
```

Если в Dokploy включён **Auto Deploy** (General → Auto Deploy + Webhook в настройках
репозитория GitHub), деплой стартует сам. Иначе — кнопка **Deploy** в панели.

Миграции применяются автоматически при каждом старте контейнера.

## Переход на домен с HTTPS

1. A-запись домена → `109.68.215.148`, TTL 300.
2. В `docker-compose.prod.yml`: раскомментировать блок `labels` у сервиса `app`
   и **удалить секцию `ports`** — иначе приложение останется доступно и по IP без TLS.
3. В Environment добавить `APP_DOMAIN=ваш-домен.ru` и заменить
   `NEXTAUTH_URL=https://ваш-домен.ru`.
4. Deploy. Traefik сам получит сертификат Let's Encrypt (резолвер `letsencrypt`).

## Решение проблем

**Сборка падает.** Шрифты лежат в репозитории (`public/fonts`, подключены через
`@font-face` в `src/app/globals.css`), поэтому сборке интернет для них не нужен —
`npm ci` по-прежнему требует доступа к реестру npm.

**`password authentication failed for user "orgchart"`.** Пароль в Environment
не совпадает с паролем внутри тома — см. раздел про пароль в начале.

**Приложение перезапускается по кругу.** Смотрите `docker logs` контейнера app.
Частая причина — незаданный `NEXTAUTH_SECRET` или недоступная база.

**Не открывается снаружи, хотя контейнеры healthy.** Порт закрыт файрволом:
`ufw allow 3001/tcp` и проверка внешнего файрвола у хостера.

**Мало памяти при сборке** (сервер меньше 4 ГБ) — добавить swap:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**Ручной прогон миграций** (обычно не нужен, они идут на старте):

```bash
docker exec -it <имя_контейнера_app> node ./node_modules/prisma/build/index.js migrate deploy
```

## Что задано в конфигурации репозитория

| Файл | Роль |
|---|---|
| `docker-compose.prod.yml` | Прод-схема: БД + приложение, порт `${APP_PORT:-3001}:3000`, healthcheck обоих сервисов, закомментированный блок Traefik для будущего домена |
| `docker-compose.yml` | Локальная разработка |
| `Dockerfile` | Сборка standalone-образа; на старте `prisma migrate deploy && node server.js` |
| `.dockerignore` | Билд-контекст без `node_modules`, `.next`, `.git`, `docs`, `tasks`, `harness` |
| `src/app/api/health/route.ts` | Проба готовности (открыта без авторизации) |
| `public/fonts/` | Inter и PT Sans Narrow (latin + cyrillic), чтобы сборка не ходила в Google Fonts |
